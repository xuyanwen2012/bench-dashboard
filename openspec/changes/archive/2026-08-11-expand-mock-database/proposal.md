# Expand Mock Database

## Why

The current mock database (`seed.db`, generated by `seed.ts`) is deliberately minimal: two
devices, one of which carries a second driver version, two branches, and model coverage
concentrated on the primary device. That is too sparse to exercise the dashboard the way
real data will — selector lists with one or two entries hide layout and filtering problems,
and cross-device / cross-driver comparisons have almost nothing to compare. A richer mockup
database — still fully separate from the production `runs.db` — lets every view, filter,
and comparison be exercised realistically before real harness data exists.

## What Changes

- Expand the fabricated dataset in `seed.ts` to a fuller mockup while keeping the same
  safety properties (opt-in script, separate `seed.db` target, `runs.db` refusal):
  - **Devices**: at least 4 (the two real phones plus plausible extras, e.g. an
    Adreno-based phone and the 780M host iGPU), **each with at least 2 driver versions**
    so device+driver comparisons work on every device.
  - **Models**: 1B / 3B / 8B on every device that plausibly fits them, with realistic
    relative throughput; at least one device still deliberately lacks 8B so
    empty-cell handling stays visible.
  - **Branches**: at least 3 (dev, stable, plus a feature branch), each with multiple
    commits; the primary device+branch keeps ≥5 commits for the trend view.
  - **Tile sweeps** (`sweep_runs` table): sweeps on more than one device and more than
    one commit per swept device, so the sweep heatmap's commit selector and the sweep
    trend view both have content.
  - Keep the existing demonstration hooks: under-sampled config, noisy config, excluded
    row, missing combinations, latest-commit-per-cell observability.
- Generation stays deterministic (fixed RNG seed); total row count grows from ~430 to
  the high hundreds but stays fast (< a few seconds) and small (< a few MB).
- No dashboard code changes expected: views, filters, and API endpoints already handle
  arbitrary dimension values.

## Capabilities

### New Capabilities

(none)

### Modified Capabilities

- `seed-data`: the "Demonstrable dataset shape" and "Compare-dimension coverage"
  requirements are strengthened — more devices with per-device driver-version pairs,
  broader model×device coverage, a third branch, multi-device/multi-commit tile sweeps
  in `sweep_runs`, and a higher row-count envelope. The safety requirements (opt-in,
  `runs.db` protection) are unchanged.

## Impact

- `seed.ts` — the only code that changes (data generation tables and loops; the DDL
  block is untouched apart from nothing — schema stays as the category split defined it).
- `seed.db` — regenerated output.
- `README.md` — the one-line description of what the seed contains.
- No changes to `db.ts`, `server.ts`, or any UI view; no API or schema changes.
- The production `runs.db` and the Python harness are unaffected.
